# iPhone 快捷指令：把 iCloud 里的血压记录导入「健康」

> 配合 Mac 端守护进程使用。守护进程把每次测量写成 JSON 文件放到
> `iCloud Drive / bp-health / inbox/`；本快捷指令负责把文件读进 iPhone「健康」App，
> 然后**把文件移到 `done/`**（不是删除 —— 这样守护进程知道"这条已导入"，不会重复补发）。

每个 JSON 文件的样子：

```json
{
  "schema": 1,
  "id": "bp-20261010-163428-115-91-69",
  "time": "2026-10-10T16:34:28",
  "time_iso": "2026-10-10T16:34:28+08:00",
  "systolic": 115,
  "diastolic": 91,
  "heart_rate": 69
}
```

- `time` 是兼容老版本的写法（无时区），**新搭建建议用 `time_iso`**（带偏移，跨时区不会错）；
- 其余字段（`flags`、`rssi`、`device`…）是排障用的，快捷指令不用管。

---

## 0. 先建好两个文件夹

在「文件」App 里建：

```
iCloud Drive / bp-health / inbox     ← 守护进程写这里
iCloud Drive / bp-health / done      ← 本快捷指令导入成功后把文件移到这里
```

（`scripts/install.sh` 会自动建；手搭的话自己点一下。）

## 搭建步骤（共 8 步）

### 1️⃣ 获取文件夹内容 + 只留血压 JSON ⭐

- 搜索「文件夹」→ 添加「**获取文件夹内容**」
- 点动作里的「文件夹」→ 选取 `iCloud Drive → bp-health → inbox`
- 如果出现「显示文稿选取器」开关 → **关闭**
- 紧接着加一步「**过滤文件**」（Filter Files）：
  - 输入 = 「文件夹内容」
  - 条件：**名称** **开头是** `bp-`

> 为什么必须过滤：inbox 里可能出现 `.DS_Store`、iCloud 同步的临时文件，
> 而「从输入中获取词典」碰到非 JSON 会直接报错，整个循环就断在第一个坏文件上。
> 如果你的系统版本没有「过滤文件」，改用「**如果** 名称 开头是 `bp-`」包住第 2~8 步，否则跳过。

### 2️⃣ 重复每一项 ⭐（最容易错的一步）

- 搜索「重复」→ 选择「**重复每一项**」（部分版本显示为「**为每个项目重复**」）
  - ❌ **不要**选「重复 N 次」——那是纯计数、不会逐个文件处理
- 重复对象选上一步的结果（过滤后的文件列表）
- 添加后会出现「重复每一项」和「结束重复」两个标记
- ⚠️ 接下来的所有动作都必须放在这两个标记**之间**

### 3️⃣ 读文件 → 词典

- 搜索「文件」→ 添加「**获取文件**」（文件 = 重复项目）
- 搜索「词典/字典」→ 添加「**从输入中获取词典**」（新版叫「从输入中获取字典」）
  - 输入：选上一步的**文件**

### 4️⃣ 取出 4 个值

- 搜索「词典/字典」→「**获取词典值**」（新版「获取字典值」），**添加 4 次**：

| 第几个 | 键（Key） | 含义 |
|--------|-----------|------|
| ① | `systolic` | 收缩压 |
| ② | `diastolic` | 舒张压 |
| ③ | `heart_rate` | 心率（⚠️ 中间是**下划线**，不是空格）|
| ④ | `time_iso` | 测量时间（老文件没有这个键时改用 `time`）|

- ⚠️ 4 个动作的「词典」参数**都选第 3 步那个「词典」输出**，不要选成上一个取值动作的结果

### 5️⃣ 写入健康：血压

- 搜索「健康」→「**记录健康样本**」
- 类型：**血压**（选中后自动出现两个值框）
- 收缩压：选 ①`systolic`
- 舒张压：选 ②`diastolic`
- 日期（点「显示更多」）：选 ④ 的时间值

### 6️⃣ 写入健康：心率

- 再加一个「**记录健康样本**」
- 类型：**心率** → 值：③`heart_rate` → 日期同上

### 7️⃣ 收尾：把文件移到 done

- 搜索「文件」→「**移动文件**」
- 文件：**重复项目**
- 目的地：`iCloud Drive → bp-health → done`

> 移动而不是删除：万一某天要回溯"这条到底导没导"，`done/` 就是账本；
> 同时守护进程看到 done 标记后，即使本地流水重放也不会再补一份。

## 运行 & 授权

1. 点 ▶️ 运行 → 首次会请求「健康」写入权限 → **允许**（血压、心率）
2. 成功后：inbox 里的文件被移到 done，「健康」App 出现对应记录
3. 如果健康里没有记录：设置 → 健康 → 数据访问与设备 → 快捷指令 → 打开「血压」「心率」的写入开关

不想等真机测量，可以先造一条测试数据：

```bash
python3 scripts/bpx1_inject.py            # 118/76 ❤68，时间=现在
python3 scripts/bpx1_inject.py --sys 132 --dia 86 --hr 74 --time 2026-11-14T09:15:00
```

## 调试技巧

- 运行后在编辑界面看**每个动作下方的灰色结果文字**：哪个是空的/不对，问题就在那里
- 想看读到的内容：在第 4 步后面加一个「**快速查看**」
- **调试期**：先把第 7 步「移动文件」拖出循环（或删掉），避免文件被移走后不好反复试
- 文件名对不上：确认过滤条件是「名称 开头是 bp-」，而不是「等于」

## 常见问题

**健康里出现重复记录**

- 多半是上一轮"写了一半失败"（比如只写了血压、心率那步报错），文件没被移动，下一轮又导入了一次；
- 也可能是这条记录被 `refill_inbox.py` 补写过 —— 但它会检查 `done/`，正常不会重复；
- 清理：健康 App → 浏览 → 血压 → 显示所有数据 → 左滑删除多余那条。

**循环跑到一半就停了**

- 99% 是 inbox 里混进了非 JSON 文件（`.DS_Store`、`.tmp`）。加第 1 步的过滤，或手工删掉这些文件；
- 新版本守护进程把临时文件写在 `staging/`，不会再污染 inbox。

**提示没有权限 / 写入失败**

- 设置 → 健康 → 数据访问与设备 → 快捷指令 → 打开「血压」「心率」写入；
- 设置 → 快捷指令 → 高级 → 允许运行脚本。

## 自动化（可选）

自动化标签 → 新建「当连接到家里 Wi-Fi 时」→ 运行本快捷指令 → 关闭「运行前询问」。

> 注意：手机不在家时文件会一直堆在 inbox 里，回家连上 Wi-Fi 才批量导入 —— 这是预期行为。
